# I-LOG

> 육아 일기와 감정 분석을 연결해 보호자의 감정 변화를 돌아볼 수 있도록 돕는 육아 기록 플랫폼

## 프로젝트 개요

I-LOG는 육아 일기, 사진·영상 기록, 실시간 아이 관찰 기능을 한곳에 모으고, 작성된 일기를 AI로 분석해 감정 변화와 리포트를 제공하는 팀 프로젝트입니다.

- 기간: 2025.10.10 - 2025.11.19
- 인원: 6명
- 담당: UI/UX 설계, 프론트엔드, 감정 분석 AI 및 서비스 연동
- 주요 기술: React, TypeScript, Zustand, Spring Boot, JPA, WebFlux, Python, RoBERTa, LLM

## 해결하려던 문제

육아 기록은 사진이나 짧은 메모로 흩어지기 쉽고, 보호자가 자신의 감정 변화를 지속적으로 돌아보기 어렵습니다. I-LOG는 기록과 관찰 경험을 하나의 서비스 흐름으로 묶고, 일기 데이터에서 감정의 흐름을 읽을 수 있도록 설계했습니다.

## 주요 기능

- 사진·영상을 첨부할 수 있는 육아 일기
- 일기 텍스트 기반 감정 분석
- 감정 변화 추이와 리포트
- 일기 사진을 활용한 육아 앨범
- WebRTC 기반 실시간 아이 관찰
- 주요 순간을 남기는 쇼츠 기능
- Google OAuth2/OIDC 기반 로그인

## 김대정의 역할과 기여

### UI/UX와 프론트엔드

- Figma로 서비스 화면과 사용자 흐름 설계
- React, TypeScript, Zustand 기반 화면 및 상태 관리 구현
- 감정 분석 결과를 사용자가 이해할 수 있는 흐름으로 시각화

### 감정 분석 AI

- 일기 텍스트를 분석하기 위한 RoBERTa 기반 감정 분석 모델 실험
- 육아 일기 도메인에 맞춘 데이터와 모델 적용 방식 검토
- 분석 결과를 서비스 백엔드와 화면에서 사용할 수 있도록 연동
- LLM을 활용한 설명 생성 흐름 설계

## 핵심 문제 해결

### 문맥을 고려한 감정 분석

단순 키워드 분류만으로는 문장의 전체 의미를 놓칠 수 있어 문맥 기반 모델을 적용했습니다. 부정적인 단어가 포함되더라도 전체 문장의 감정이 다른 사례를 확인하며, 모델 결과를 그대로 노출하기보다 문맥과 후속 설명을 함께 다루는 방향을 선택했습니다.

### AI 결과와 서비스 흐름 연결

모델 호출 자체보다 결과를 저장하고 사용자에게 일관되게 보여주는 과정이 중요했습니다. 분석 요청, 결과 저장, 리포트 표시의 흐름을 프론트엔드·백엔드·AI 영역으로 나누어 연결했습니다.

### 제한된 일정 안에서 범위 조정

AI와 프론트엔드를 함께 담당하면서 초기 기획 범위가 일정에 비해 넓다는 점을 경험했습니다. 핵심 사용자 흐름을 먼저 완성하고 부가 기능의 우선순위를 조정하며, 기술 선택뿐 아니라 일정과 범위 관리도 제품 완성도에 직접 영향을 준다는 점을 배웠습니다.

## 회고

I-LOG를 통해 새로운 기술을 서비스에 적용할 때 모델 성능만큼 사용자 흐름, 일정, 실패 상황을 함께 설계해야 한다는 점을 배웠습니다. 이후에는 AI 결과의 평가 기준과 운영 지표를 더 명확히 정의하고, 기능별 완료 조건을 초기에 합의하는 방식으로 개선하고자 합니다.
