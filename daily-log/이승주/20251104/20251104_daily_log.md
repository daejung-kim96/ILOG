### 📝 회고

- 스프링 시큐리티 oauth2Login() 은 2개의 필터체인을 추가한다.
  - 1번 필터체인은 oauth2/특정 url 로오는 요청을 가로채 사용자를 로그인 폼으로 redirect 시킨다. 이 때 application.yml 에 정의된 코드,시크릿,redirect url을 활용한다.
  - 2번 필터체인은 redirecturl 요청을 가로채 사용자 구글 서버 AT를 발급받고 해당 AT로 UserService를 호출한다.
  - 이 때 custom UserService로 사용자정보를 받아와 처리한다.
  - Attribute oauth2 요청을 받은 다양한 사이트는 서로다른 key value로 값을 반환한다 이를 하나의 attribute로 받아 처리하도록 변경한다.
  - 이렇게 생성된 user Attribute를 토대로 유저정보를 저장하거나 확인한 후 principalDetail 객체를 반환한다.
  - 이 객체를 토대로 authentication 객체를 생성하고 SuccessHandler로 후속 처리를 진행한다.
  - 이 authentication 객체는 jwt의 stateless 상태 지향을 위해 즉시 사라진다.
  - authentication 객체의 소멸로 msa에선 각 ms가 authentication 객체를 생성시키는 security로직이 필요해지는데, 이는 gateway가 인가를 담당하도록 하는 중앙집중형 방식으로 해결할 수 있고, 각 ms 가 gateway를 신뢰하여 전달받은 header userId 를 토대로 mock authentication 을 생성하여 security가 제공하는 다양한 method를 활용하는 방법이 있으나, 본 프로젝트에선 userId를 비즈니스 로직으로 처리하도록 한다.
- 아웃박스 패턴은 데이터와 해당 데이터에 대한 이벤트 발행의 정합성을 보장하기 위해 하나의 트랜잭션으로 데이터, 이벤트를 관리하기 위한 방법이다.
  - 현재 Command로 유저가 생성되면 user ms 의 사용자 정보 책임과 auth ms 의 사용자 인증 책임이 분리되어 있어 둘 모두 하나의 트랜잭션내에서 정합성이 보장되어야 하는 진실 공급원이다.
  - 이를 위해 outbox entity를 구현하고 repository로 outbox를 저장하는 단일 transaction을 구현하였다.
  - 해당 db에 업로드된 이벤트를 발행하는 방법은 두가지가 있다.
  - 1번 polling 이 방식은 이벤트의 발행이 즉각적이지 않아 비권장
  - 2번 CDC(Change Data Capture) 실시간 데이터 감시를 위해 새로운 ms 를 구현한다. kafka 클러스터 또는 debzium이 활용된다 향후 알아볼것
