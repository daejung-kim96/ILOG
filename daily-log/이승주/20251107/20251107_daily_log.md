### 📝 회고

- Handler Factory 는 팩토리 Handler를 호출하며 eventType, payload를 전달하여 eventType에 맞는 Handler를 호출 Handler가 구현한 process에 payload를 넣어 액션을 실행한다.
  - 쓰기 db에 업데이트 하는것은 command임이 자명하다. 하지만 읽기 db에 업데이트 하는것은 query전용 db에 업데이트 행위를 하는것이다.
  - query용 db에 작업을 하는것이라 query작업이라 생각할 수 있지만 이또한 command 작업이다. 이는 프로젝션 업데이트를 수행하기 때문이며, query 작업은 오직 query dsl을 수행할 대만 이다.
- repository가 어느 DB에 접속하는지는 config 설정으로 제어할 수 있다.
  - 각 db에 접속제어 설정을 따르며 이 때 transaction 설정 또한 할 수 있다. 이 때 하나의 트랜잭션에서 read, write db를 동시에 사용할 때 트랜잭션은 write db의 트랜잭션을 따라 read와 write db의 원자성을 동시에 보장하진 않는다. 하지만 이는 자연스러운 현상으로 read DB가 누락되는 경우는 batch 작업이나 후속 보상로직으로 해결해야 한다.
- kafka 토픽과 파티션은 kafak-init이라는 추가 설정으로 진행할 수 있다.
  - 이 작업은 docker compose 에 정의되어야 한다. 배포 개발 환경과 상관없이 통일된 환경을 제공해야 한다. topic 과 파티션은 init으로 주입하고 contorller에 의해 분배된다.
